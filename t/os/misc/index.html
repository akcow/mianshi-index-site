其他题目 12 题

Go的GMP模型中，当一个G阻塞在系统调用时，M和P分别会发生什么变化？

阻塞的是M（内核线程），G跟着M一起挂起；此时P会立刻解绑，被其他空闲M抢走继续跑别的G。等系统调用返回，原M会尝试重新获取P——抢到了就继续执行这个G，抢不到就把G放回全局队列，自己休眠。

回答要点
  1. 明确M是真正阻塞在syscall的实体
  2. P必须解绑以避免调度饥饿
  3. M返回后需重新竞争P，失败则G入全局队列
  4. 需对比网络I/O（走netpoll，不阻塞M）说明差异
展开讲讲

Go 运行时要求 M 在阻塞系统调用前主动解绑 P，否则会导致其他 Goroutine 长期无法被调度——因为 P 是运行 G 的必要资源，而每个 P 同一时刻只能绑定一个 M（runtime.m.p != nil 且 p.mcache != nil 依赖 M 存在）【Go 源码：src/runtime/proc.go:entersyscall()】。若不解绑（如通过 syscall.Syscall 直接阻塞 M 而不调用 entersyscall），P 将被独占，全局队列或本地队列中的就绪 G 无法获得执行机会，引发调度饥饿。解绑后 M 进入 m.locked = 0 状态并调用 exitsyscall() 尝试重新获取 P；失败则其 G 被推入全局运行队列（globrunqput()），由其他空闲 M 抢占执行【Go 源码：src/runtime/proc.go:exitsyscall()】。网络 I/O 不阻塞 M，是因为 netpoll 利用 epoll/kqueue 等异步机制，将 fd 注册后立即返回，M 继续执行其他 G，仅当事件就绪时由 netpoll 回调唤醒对应 G——这依赖于 runtime.pollDesc 和 netpoll 的集成，而非同步 syscall 【Go 官方文档：Design Documents → Netpoller】。

最小示例：syscall.Read(fd, buf) 会触发 entersyscall() 解绑；而 conn.Read()（底层走 netpoll）不会导致 M 阻塞，其 goroutine 被挂起在 runtime.netpollblock()，M 可继续调度其他 G。

CPU切换线程的整个过程是怎么样的？

分三步：先由硬件触发中断，CPU自动将旧线程的SS、RSP、CS、RIP、FLAGS压入其内核栈；再由内核调度器选新线程，若跨进程则切换页表+刷新TLB；最后从新线程内核栈弹出通用寄存器，执行iret指令恢复SS/RSP/CS/RIP，回到用户态继续执行。

回答要点
  1. 明确硬件自动保存的寄存器集合（至少SS/RSP/CS/RIP/FLAGS）
  2. 指出内核栈是线程私有且切换核心
  3. 说明跨进程切换需额外处理页表和TLB

读操作需要加锁吗？为什么？

需要加锁，原因有三：一是硬件层面，CPU缓存不一致可能导致读到旧值；二是编译器可能把读操作优化成寄存器缓存，跳过内存访问；三是32位机读int64非原子，可能读到撕裂值。加锁通过内存屏障解决全部问题。

怎么理解工作内存和内存屏障？

Go没有JVM那种显式‘工作内存’概念，但多核下每个goroutine仍面临缓存不一致和指令重排。内存屏障就是CPU指令，比如LFENCE/STOREFENCE，它强制屏障前的读写必须完成，屏障后的才能开始，并刷Store Buffer、清失效队列，确保其他核看到最新值。

  2. 说出内存屏障的两类作用：禁止重排+保证可见性
  3. 举出具体指令名（如x86的MFENCE）

进程和线程的区别是什么？

进程是资源分配单位，有独立地址空间、文件描述符表、信号处理等；线程是CPU调度单位，同一进程内线程共享地址空间、全局变量、打开的文件，但有独立栈、寄存器、线程ID；创建进程开销大，线程开销小；线程间通信快，进程间需IPC。

  3. 对比创建开销与通信成本
展开讲讲

进程作为资源分配单位，其设计核心是提供内存隔离与权限边界——每个进程拥有独立的虚拟地址空间，由 MMU 硬件和内核页表共同保障，避免一个进程崩溃或越界访问影响其他进程（POSIX.1-2017 §3.285, ‘process’ definition）。若取消此隔离（如早期 DOS 单地址空间模型），系统将丧失基本稳定性与安全性，无法支持现代多任务与保护模式。线程则复用进程的地址空间与内核对象（如打开的文件描述符、信号处理设置），仅独占栈、寄存器上下文和线程局部存储（TLS）；Linux 中 clone() 系统调用通过 CLONE_VM | CLONE_FILES | CLONE_SIGHAND 标志组合实现此语义（Linux man-pages 6.03: clone(2)）。若线程也独占地址空间，则失去轻量级优势，退化为进程，违背 POSIX 线程（pthreads）的设计目标（IEEE Std 1003.1-2017 §2.8.4）。创建开销差异源于内核数据结构：进程需复制页表、VMA、文件描述符表等，而线程仅需分配内核栈与 task_struct（Linux kernel source: kernel/fork.c, copy_process() vs copy_thread_tls()）。

示例：Linux 下线程共享文件描述符

// 主线程打开文件后，新线程可直接 read() 同一 fd
int fd = open("/tmp/test", O_RDONLY); // fd=3
pthread_create(&tid, NULL, thread_func, &fd);
// thread_func 中：read(3, buf, 100); // 成功，因 CLONE_FILES 生效
