这一场问了什么

1.为什么选择这个行业 / 这个岗位？和你之前的经历跨度这么大，怎么解释？
回答要点
  1. 给一条自洽的线索：过去的经历如何指向现在的选择，而不是否定过去
  2. 要具体：说出对这个行业的真实认知，不能只说「感兴趣」
  3. 给出可验证的动作：为此做过什么（项目、实习、研究、内容输出）
  4. 跨行时强调可迁移能力（数据分析、结构化思维、沟通）
完整解析（含追问与踩坑）→
2.你未来 3 年的职业规划是什么？
回答要点
  1. 分阶段：先补什么能力、再承担什么责任
  2. 方向和应聘岗位一致
  3. 给出判断标准：三年后你希望自己具备什么能力，而不只是什么职级
完整解析（含追问与踩坑）→
3.你遇到过最困难的事 / 最难完成的任务是什么？怎么解决的，收获是什么？
回答要点
  1. 选一个有技术或协作含量的困难，别选「环境配了一天」
  2. 讲清：现象 → 假设 → 验证 → 结论 的排查链
  3. 有可迁移的收获，说明后来怎么避免同类问题
完整解析（含追问与踩坑）→
4.当你和团队技术同学对「模型效果是否可上线」产生冲突时，你怎么解决？
回答要点
  1. 回到共同标准：事先约定的验收口径与灰度策略，而不是谁的职级高
  2. 把分歧量化：差在哪几个 case、影响多少比例用户、能否灰度验证
  3. 给技术方决策权在技术风险上，产品方承担体验取舍
  4. 兜底方案：灰度、开关、可回滚
完整解析（含追问与踩坑）→
5.面对压力时你有什么应对方法？
回答要点
  1. 给具体方法，不要只说「调整心态」
  2. 举例：一次高压情境下你怎么拆解、怎么求助、结果如何
  3. 能区分健康应对和硬扛
完整解析（含追问与踩坑）→
6.如何定义和统计 AI 产品的「无效回复率」或「点踩率」？
回答要点
  1. 先定义「无效」：答非所问、拒答、事实错误、格式错误、无信息量，要分类而不是一个笼统概念
  2. 口径来源：点踩动作、用户重问、会话中止、人工标注抽样
  3. 分母要选对：按回复条数、按会话、按活跃用户，三者含义完全不同
  4. 代价意识：点踩率低不等于体验好，大部分不满的用户直接走了不点踩
完整解析（含追问与踩坑）→
7.AI 产品经理应该更看重「回复的逻辑严密性」还是「回复的类人情感化」？
回答要点
  1. 按场景分：工具型（代码、法律、医疗）重逻辑；陪伴型、客服型重情感
  2. 按用户分：专业用户容忍冷硬，大众用户更需要自然表达
  3. 两者冲突时以任务成功率优先，情感化是加分项不是基础项
完整解析（含追问与踩坑）→
8.在你做的 AI 项目里，你真正解决的是信息获取效率问题，还是内容创作门槛问题？
回答要点
  1. 给出明确归类，并说清判断依据
  2. 两个方向的产品逻辑不同：效率类拼准确与速度，创作类拼质量与风格可控
  3. 承认可能的双重属性，但要指出主次
  4. 落到指标：效率类看节省时间，创作类看产出采纳率
完整解析（含追问与踩坑）→
9.假设 AI 助手的周留存率（WAU）下滑了 10%，你如何系统性拆解原因？
回答要点
  1. 先验证数据：口径变更、埋点故障、统计周期异常
  2. 分层拆：新老用户、渠道来源、机型、地区，看是普跌还是结构性下滑
  3. 内因：模型效果退化、响应变慢、功能改版、成本控制导致降级
  4. 外因：竞品发版、行业事件、季节性（假期/开学）
  5. 落到可验证假设，给出验证所需的数据
完整解析（含追问与踩坑）→
10.模型推理成本过高导致亏损，但用户追求极致长文本输入，你怎么处理？
回答要点
  1. 分层定价：免费额度 + 阶梯付费 + 长文本单独计价
  2. 技术侧降本：缓存、路由到小模型、RAG 替代长上下文、摘要预处理
  3. 体验侧设计：明确告知限制，提供压缩/分段入口，而不是静默降级
  4. 用数据定阈值：算出单用户毛利临界点，据此设免费额度
完整解析（含追问与踩坑）→
11.让你负责一个针对职场新人的 AI 生产力工具，你会从哪个细分场景切入？
回答要点
  1. 选场景的三个判据：高频、痛点强、AI 有显著增量（不是硬凑）
  2. 职场新人的典型场景：周报/会议纪要、汇报材料、信息检索、话术撰写
  3. 给出优先级：先做哪个、为什么其他先不做
  4. 说清冷启动怎么获客、怎么验证价值
完整解析（含追问与踩坑）→
12.生成式 AI 会终结传统的内容创作者生态吗？如果不会，你会怎么设计激励机制？
回答要点
  1. 给明确立场并说清依据，不要两头讨好
  2. 拆分创作者类型：效率型（会被替代）、风格型（AI 难复制）、信任型（人格化背书）
  3. 激励设计要落到机制：收益分配、原创溯源、质量分层、曝光倾斜
  4. 识别风险：内容同质化、版权争议、平台审核成本
完整解析（含追问与踩坑）→
13.假如 AI 能自动写代码、画图、做原型了，你作为 PM 的核心价值是什么？
回答要点
  1. AI 替代的是执行，不替代的是「决定做什么、为谁做、值不值得做」
  2. 核心价值：定义问题、做取舍、承担结果、组织资源
  3. 举具体例子说明自己做过这类判断，而不是空谈
  4. 承认能力边界变化：会用 AI 的 PM 和不会用的会分化
完整解析（含追问与踩坑）→
14.介绍一下你参与的项目，以及你如何定义这个 AI 功能的成功指标？
回答要点
  1. 项目：目标用户、核心问题、方案、你的角色
  2. 指标分层：北极星（业务价值）+ 过程指标（使用深度）+ 质量指标（效果）
  3. 说清为什么选这个北极星，而不是别的
完整解析（含追问与踩坑）→
15.如何发现用户对「AI 搜索」或「长文档分析」功能的核心痛点？
回答要点
  1. 定量：漏斗（提问 → 追问 → 采纳 → 复制）、重问率、会话中止率、功能弃用点
  2. 定性：用户访谈、可用性测试、录屏回放、客服工单归类
  3. 场景还原：在什么任务下用、失败时的替代方案是什么
  4. 区分「说不出的痛」和「说得出的需求」
完整解析（含追问与踩坑）→
16.腾讯元宝（或 ima）与字节的豆包（或 Cici）核心差异在哪？
回答要点
  1. 定位差异：元宝依托微信生态与腾讯内容资产，豆包依托抖音流量与字节推荐能力
  2. 能力差异：长文本、多模态、插件生态、联网检索的侧重不同
  3. 分发差异：一个是社交流量池，一个是内容流量池
  4. 能说出各自的短板，而不只是各自的好
完整解析（含追问与踩坑）→
17.为什么要针对不同专业领域（法律、医疗、编程）定制不同的 Agent 插件？这是笔划算的账吗？
回答要点
  1. 收益侧：垂类准确率提升、专业用户付费意愿更高、可形成壁垒
  2. 成本侧：数据获取与标注、评测体系搭建、持续维护、合规审查
  3. 判断框架：单领域 ROI = 该领域用户规模 × 付费转化 × ARPU ÷（研发 + 维护 + 合规）
  4. 结论要带排序：先做哪个领域，为什么
完整解析（含追问与踩坑）→
18.这个 AI 助手后续在「多模态交互」方向有哪些可优化的点？
回答要点
  1. 输入侧：图片、语音、文件、屏幕共享，各自对应什么高频场景
  2. 输出侧：图表、卡片、可交互组件，比纯文本更能承载结构化结果
  3. 优先级按场景收益排，而不是按技术炫酷程度
完整解析（含追问与踩坑）→
19.AI 功能应该做成独立 App（如元宝），还是嵌入微信 / QQ 作为插件？专而精 vs 大而全怎么选？
回答要点
  1. 嵌入的优势：零获客成本、场景自然、调用频次高
  2. 独立的优势：交互不受宿主限制、可承载复杂任务、品牌独立
  3. 判断依据：使用频次、任务复杂度、是否需要长会话、宿主是否限制能力
  4. 给出条件式答案：什么阶段做什么形态，而不是二选一
完整解析（含追问与踩坑）→
