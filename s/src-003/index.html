1.开发这个项目的过程中遇到了哪些困难，怎么解决的？
回答要点
  1. 选一个真实的、有技术含量的困难，不要选「环境配了一天」
  2. 讲清排查过程：现象 → 假设 → 验证 → 结论
  3. 有可复用的收获，最好能说出后来怎么预防同类问题

2.ReAct 模式和 Plan 模式有什么区别，各自适用于什么场景？
回答要点
  1. ReAct：思考-行动-观察循环，每步依赖上一步结果，适合探索型、信息不完备的任务
  2. Plan：先产出完整计划再执行，适合步骤可预先枚举、需要全局最优的任务
  3. ReAct 灵活但容易绕路、成本不可控；Plan 可控但对环境变化适应性差
  4. 实践中常见混合：先 Plan 出骨架，执行中在子任务内用 ReAct
完整解析（含追问与踩坑）→
3.如何避免上下文压缩之后，模型忘记用户之前提出的重要需求？
回答要点
  1. 把用户约束单独抽成结构化字段（requirements），每次请求都带上，不参与压缩
  2. 压缩时用固定模板强制包含约束段
  3. 在系统提示里重申当前目标清单
  4. 加校验：输出前检查是否违反已知约束
完整解析（含追问与踩坑）→
4.Agent 陷入死循环或反复调用同一工具，怎么检测和处理？
回答要点
  1. 检测：对（工具名 + 参数）做指纹，连续重复 N 次即判定；也可用状态哈希比对
  2. 原因：工具返回值没有提供有效信号、错误信息太模糊、任务本身无解、prompt 缺少退出指引
  3. 处理：注入反思提示、切换策略、熔断并人工介入、回退到上一个成功状态
  4. 根治：让工具返回结构化错误码，prompt 里明确「同一工具失败两次就换方案」
完整解析（含追问与踩坑）→
5.一个完整的 Agent 记忆系统该怎么设计，包含哪些模块？
回答要点
  1. 三层：工作记忆（当前上下文）、会话记忆（本次对话摘要）、长期记忆（跨会话用户画像与事实）
  2. 模块：写入（提取候选记忆）、存储（结构化 + 向量）、检索（相关性 + 时效）、遗忘（TTL 与衰减）、冲突消解
  3. 检索常见做法：向量召回 + 关键词 + 时间衰减加权，再 rerank
完整解析（含追问与踩坑）→
6.当前对话的 Context 和长期 Memory 有什么区别，各自解决什么问题？

当前会话记忆生命周期最短，只服务本轮对话，强调实时性和指代消解；每日摘要记忆按天压缩多轮交互，侧重阶段性事实沉淀；长期用户记忆生命周期最长，存稳定偏好和身份信息，隐私等级最高，必须显式授权。三者召回频次、置信阈值、存储位置都不同。

回答要点
  1. Context 是本次推理的输入窗口，有限且随请求消失；Memory 是跨会话持久化的外部存储
  2. Context 解决「这一轮该看到什么」，Memory 解决「长期记住什么」
  3. Memory 需要被检索后注入 Context 才生效，两者是存储与装载的关系
完整解析（含追问与踩坑）→
7.Agent 中的 Memory 信息如何进行提取、存储和检索？
回答要点
  1. 提取：对话结束后用 LLM 抽取「值得记住的事实」，输出结构化条目（主体、谓词、值、置信度、时间）
  2. 存储：结构化字段 + 向量双写，便于精确查询和语义召回
  3. 检索：query 改写 → 向量召回 top-k → 时间衰减与置信度加权 → rerank → 注入
  4. 去重与更新：同一主体同一谓词做覆盖或版本化
完整解析（含追问与踩坑）→
8.为什么一些记忆管理、上下文压缩任务可以交给小模型完成？
回答要点
  1. 这类任务是「信息筛选与摘要」，不需要复杂推理，小模型够用
  2. 调用频次高（每轮或每次会话都要跑），成本敏感
  3. 延迟敏感，小模型响应快，不阻塞主链路
  4. 大模型留给需要推理和规划的决策环节
完整解析（含追问与踩坑）→
9.讲清楚 Agent 项目从用户输入到最终输出的全链路，每一环的输入输出分别是什么？
回答要点
  1. 用户输入 → 拼装上下文（system、历史、工具定义、记忆）→ 调模型
  2. 模型返回纯文本或 tool_call；tool_call 进参数校验 → 权限校验 → 执行（沙箱）→ 结果回灌
  3. 循环直到模型输出终止信号或触发 max_steps；最后一次输出做后处理返回用户
  4. 每一环能明确说出输入是什么、输出是什么、失败怎么处理
完整解析（含追问与踩坑）→
10.Agent 拥有大量工具时，怎么避免工具描述导致 Prompt 过长？
回答要点
  1. 工具检索：按 query 语义召回 top-k 工具，只注入相关的
  2. 分层：先给工具分类目录，模型选定类目再加载该类目下的工具
  3. 按需加载（MCP 的 tools/list 分页或按 server 粒度挂载）
  4. 精简描述：每个工具描述控制在必要信息内，长文档移到工具返回里
完整解析（含追问与踩坑）→
11.Prompt Cache 是什么，为什么能提升模型调用效率，如何提高命中率？
回答要点
  1. 把前缀部分的 KV 缓存下来，命中时跳过重复计算，省算力也省延迟
  2. 命中前提是前缀完全一致，所以要把稳定内容放前面、变化内容放后面
  3. 提高命中率：固定 system prompt、工具定义顺序稳定、避免在开头插入时间戳等动态内容
完整解析（含追问与踩坑）→
12.Multi-Agent 系统中，不同 Agent 之间应该怎么划分职责，任务怎么拆分？
回答要点
  1. 按能力边界拆（检索、编码、审核）而非按步骤流水拆
  2. 拆分的判据：子任务是否可独立验证、是否需要不同工具集或不同模型
  3. 要有明确的输入输出契约，否则接口处会大量信息丢失
  4. 别为了多 Agent 而多 Agent，单 Agent 能解决就别拆
完整解析（含追问与踩坑）→
13.多个子 Agent 之间如何进行通信和任务协作？
回答要点
  1. 常见拓扑：中心编排（orchestrator）+ 星型、层级、黑板共享状态
  2. 通信内容要结构化（任务描述、约束、期望输出格式），不要传自然语言自由发挥
  3. 共享状态存外部存储，Agent 无状态化，便于重试和横向扩展
  4. 冲突仲裁：定优先级规则、投票、或回交给编排者裁决
完整解析（含追问与踩坑）→
14.如果让你优化这个 Agent 系统，你会优先从哪些方向入手？
回答要点
  1. 先看数据：成功率、成本、延迟哪个离目标最远
  2. 典型优先级：先修高频 badcase（收益最大），再降成本（小模型替换、缓存），最后提上限
  3. 要有度量才谈得上优化，没有评测体系的优化都是拍脑袋
  4. 给出取舍理由，说明为什么这项排在前面
完整解析（含追问与踩坑）→
15.判断一棵二叉树是否为平衡二叉树
回答要点
  1. 自底向上：后序遍历返回子树高度，一旦不平衡返回 -1 剪枝
  2. O(n) 复杂度，不要自顶向下重复计算高度
  3. 空树是平衡的
