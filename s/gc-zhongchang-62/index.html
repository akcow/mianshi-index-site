一面 未标注 GoClub 互联网 7 道题 2026-11-09

这一场问了什么

1.数据库表结构怎么设计？

我按三层解耦设计：storage_systems存云盘/HDFS等接入信息；directories用parent_id实现目录树，支持路径查询；files表存文件核心元数据，并通过directory_id关联目录。不把文件列表放目录表里，避免字段膨胀和更新困难。如果一个逻辑文件跨多个物理存储，再加file_sources表做多对多映射。

回答要点
  1. 区分存储系统、目录、文件三层实体
  2. 目录树用邻接表（parent_id）而非嵌套集
  3. files表通过foreign key关联directory_id而非反向存储列表
  4. 能说明为何不用目录表存文件ID数组
  5. 提出file_sources表应对多源存储场景

2.整体架构如何拆分？

我拆成五块：API网关统一入口；元数据服务管MySQL里的目录和文件；存储适配器层屏蔽云盘/HDFS/本地盘差异；搜索服务消费消息队列事件，维护ES索引；下载服务负责权限校验、任务调度和流式ZIP生成。所有跨存储操作都走适配器，变更都发事件，不直接调用。

回答要点
  1. 明确划分元数据、存储、搜索、下载四大核心服务
  2. 指出消息队列作为元数据变更与索引更新的解耦媒介
  3. 说明适配器层对不同存储SDK的封装职责
  4. 下载服务需支持同步小文件流式响应和异步大任务
  5. 强调各模块间无直接依赖，靠接口和事件通信
完整解析（含追问与踩坑）→
3.关键接口和抽象类有哪些？

我定义StorageAdapter接口，统一List/Stat/Open方法，每个存储实现它；FileRepository封装MySQL增删查改，隔离SQL细节；还抽象DirectoryService处理树形操作，SearchService封装ES查询，DownloadJobService管理异步任务。所有业务逻辑只依赖interface，不碰具体实现。

回答要点
  1. StorageAdapter必须包含List/Stat/Open三个核心方法
  2. FileRepository需支持按FileQuery条件查询
  3. 明确interface与具体实现分离的设计意图
  4. 能举例说明某业务逻辑如何通过依赖注入使用这些接口
  5. 指出仓储模式（Repository）用于解耦持久化
完整解析（含追问与踩坑）→
4.会用到哪些设计模式？

四个关键模式：适配器——把各家存储SDK转成统一StorageAdapter；工厂——根据storage_systems.type创建对应适配器实例；策略——为不同存储选不同ZIP读取或目录遍历策略；观察者——文件变更时发布事件，索引服务订阅处理。仓储模式也用了，把MySQL操作封在FileRepository里。

回答要点
  1. 准确匹配适配器模式与StorageAdapter实现
  2. 工厂模式需根据type字段动态创建实例
  3. 策略模式体现在可插拔的遍历/压缩/读取行为
  4. 观察者模式用于解耦文件变更与索引更新
  5. 仓储模式指FileRepository对MySQL的封装
完整解析（含追问与踩坑）→
5.如何实现跨存储系统搜索？为什么使用搜索引擎？

我把文件名、路径、大小、更新时间等元数据同步到Elasticsearch，查的时候先搜ES再回查MySQL拿权限和最新状态。不用MySQL是因为它不擅长分词、模糊匹配和高并发全文检索；ES倒排索引快，还能做相关性排序。同步用Outbox+消息队列保证可靠，存量走全量扫描，增量靠事件。

回答要点
  1. 明确ES存检索字段，MySQL存强一致元数据
  2. 指出MySQL不适合分词/前缀/模糊等复杂查询
  3. 同步机制含Outbox事务保障+幂等upsert+版本控制
  4. 说明全量+增量双阶段同步策略
  5. 提及短暂延迟下回查MySQL兜底
完整解析（含追问与踩坑）→
6.不同文件系统的文件如何打包成 ZIP？

客户端传文件ID或目录ID，下载服务先校验权限和总大小；然后按存储类型分组，调各自StorageAdapter读取；小文件流式写HTTP响应，大文件走异步任务生成ZIP存临时对象存储；ZIP内路径用用户视角相对路径，绝不暴露底层object_key；写ZIP必须串行，但读取可以并发，用有界缓冲控内存。

回答要点
  1. 权限校验和大小限制前置执行
  2. 按存储类型分组复用连接并支持批量读取
  3. 区分同步流式响应与异步任务两种路径
  4. ZIP内路径脱敏，不泄露底层存储真实路径
  5. 读取并发+ZIP写入串行+流式传输三者协同
完整解析（含追问与踩坑）→
7.异步下载场景还有哪些优化？

四点优化：一是按存储endpoint分组，复用连接并调批量接口；二是Worker Pool限流+超时+有界队列，防打挂下游；三是读取和ZIP写入间加有界缓冲，用背压控内存；四是缓存高频ZIP，任务用幂等键，失败只重试分片并记录进度。对已压缩文件跳过ZIP压缩，减少CPU。

回答要点
  1. 分组复用连接并利用存储方批量API
  2. Worker Pool需配置并发数、超时、队列长度三要素
  3. 有界缓冲实现读写速率解耦与内存保护
  4. 幂等键设计+分片重试+进度记录构成可靠任务框架
  5. 缓存策略针对常用目录或重复下载文件
