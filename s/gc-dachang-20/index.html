1.Redis 里面有哪些数据类型，分别适合什么场景？

String 适合做缓存、计数器、分布式锁；Hash 存对象字段比如用户信息；List 当简单队列或消息广播；Set 做去重、标签系统、共同关注；ZSet 搞排行榜、延时队列、按分数排序查询。还用过 Bitmap 做日活统计，HyperLogLog 估 UV。

  1. 准确说出 5 种基础类型（String/Hash/List/Set/ZSet）及其典型场景
  2. 至少补充 1 种扩展结构（Bitmap/HyperLogLog/Stream）及用途
  3. 能区分 List 和 ZSet 在排序需求上的本质差异

2.Redis 为什么快？

核心三点：纯内存操作避免磁盘 IO；单线程避免上下文切换和锁竞争；多路复用 I/O 模型高效处理并发连接。另外，简单数据结构和命令原子性也减少了复杂度开销。

回答要点
  1. 指出内存存储是基础前提
  2. 强调单线程 + I/O 多路复用的组合设计
  3. 说明数据结构简单和命令原子性对性能的辅助作用
完整解析（含追问与踩坑）→
3.讲一下 Go 的垃圾回收（GC）机制。

Go 从 1.5 开始采用并发三色标记清除算法：初始 STW 扫描根对象并开启写屏障，之后标记与用户代码并发执行；第二次 STW 清理未标记对象。关键点是混合写屏障避免漏标，且 STW 时间已压缩至百微秒级。

回答要点
  1. 明确说明是三色标记-清除算法
  2. 指出写屏障的作用是防止漏标
  3. 强调两次 STW 阶段及其各自任务

4.MySQL 有哪些索引类型？

逻辑上分主键、唯一、普通、联合索引；物理上InnoDB只有聚簇索引（叶子存整行）和二级索引（叶子存主键）。特别注意：二级索引查非主键列要回表，但自适应哈希索引（AHI）能加速热点查询。

回答要点
  1. 区分逻辑分类（功能）和物理分类（存储结构）
  2. 明确聚簇索引=主键索引，二级索引叶子节点存主键值
  3. 提到AHI是InnoDB自动维护的优化机制
完整解析（含追问与踩坑）→
5.MySQL 有哪些锁？事务隔离级别有哪些？不同隔离级别下这些锁如何工作？

锁类型：行锁（记录锁、间隙锁、临键锁）、表锁、意向锁。隔离级别：读未提交、读已提交、可重复读、串行化。RR 下默认用临键锁（记录锁+间隙锁）防止幻读；RC 下只用记录锁，不加间隙锁，所以可能幻读。

回答要点
  1. 准确说出四种隔离级别名称
  2. 区分记录锁、间隙锁、临键锁三者关系
  3. 明确 RR 用临键锁防幻读，RC 不加间隙锁
完整解析（含追问与踩坑）→
6.MySQL 有哪些日志？各自作用是什么？

主要有三种：redo log（InnoDB 引擎层，保证崩溃恢复，循环写，物理日志）；undo log（引擎层，支持回滚和 MVCC，逻辑日志）；binlog（Server 层，用于主从复制和恢复，逻辑日志，追加写）。三者协同保障 ACID。

回答要点
  1. 分别说明 redo、undo、binlog 的层级（引擎/Server）
  2. 指出 redo 保崩溃恢复、binlog 保复制与归档、undo 保回滚与 MVCC
  3. 强调 redo 是物理日志、binlog/undo 是逻辑日志
完整解析（含追问与踩坑）→
7.Kafka 为什么可以处理高吞吐？

Kafka 高吞吐主要靠五点：一是顺序追加写日志，磁盘效率远高于随机写；二是分区并行，把 topic 拆成多个 partition，生产和消费都能水平扩展；三是批量处理，发、写、拉都成批做，省网络和系统调用；四是重度依赖 page cache，读写优先走内存；五是 sendfile 零拷贝，避免用户态和内核态间反复拷数据。

回答要点
  1. 顺序追加写磁盘
  2. partition 实现并行扩展
  3. 批量发送/写入/拉取
  4. 利用 page cache 减少 IO
  5. 零拷贝（sendfile）优化网络发送
完整解析（含追问与踩坑）→
8.HTTP 和 HTTPS 有什么区别？
回答要点
  1. HTTPS = HTTP + TLS，默认 443 端口
  2. HTTP 明文传输，HTTPS 加密，防窃听、防篡改、防冒充
  3. HTTPS 通过证书链验证服务端身份，HTTP 没有身份验证
  4. 代价：握手增加 RTT，有加解密开销，需要证书维护

9.TCP 为什么要四次挥手？如果省略第四次挥手，会有什么问题？

四次挥手因 TCP 全双工，双方需独立关闭发送方向。第一次 FIN 关 A→B 发送，第二次 ACK 确认，第三次 FIN 关 B→A 发送，第四次 ACK 确认。若省略第四次，B 不知 A 是否收到 FIN，可能重发 FIN，导致 A 无法进入 CLOSED，B 卡在 LAST_ACK，连接异常残留。

回答要点
  1. 说明全双工导致需双方独立关闭发送通道
  2. 准确描述四次交互中每次的发起方和含义
  3. 指出省略第四次会导致 B 卡在 LAST_ACK、A 无法释放资源
完整解析（含追问与踩坑）→

11.请手撕代码：LeetCode 162. 寻找峰值。

峰值定义是 nums[i] > nums[i-1] 且 nums[i] > nums[i+1]。关键观察：若 nums[mid] < nums[mid+1]，右侧必有峰（因右边界 nums[n-1] > -∞），向右搜；否则向左搜。时间 O(log n)，只需比较 mid 和 mid+1。

回答要点
  1. 正确写出二分框架（left/right 初始化与更新）
  2. 判断条件基于 nums[mid] 与 nums[mid+1] 大小关系
  3. 处理边界（如数组长度为 1 或 2）
