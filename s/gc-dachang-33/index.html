1.能不能介绍一下 K8s 的架构，申请 Pod 的一个执行流程？

K8s 分控制面和工作节点：控制面有 apiserver（入口）、etcd（状态存储）、scheduler（调度）、controller-manager（副本管理）；工作节点有 kubelet（执行Pod）、容器运行时、kube-proxy。Pod 创建流程是：kubectl 提交 → apiserver 认证鉴权 → 写入 etcd → scheduler 选节点并绑定 → kubelet 拉镜像、启容器、上报状态。

回答要点
  1. 明确区分控制面/数据面及其核心组件
  2. 按顺序说出从提交到容器启动的关键步骤（含 apiserver、etcd、scheduler、kubelet 四环节）
  3. 点出关键机制：声明式、watch 机制、CRI 调用
完整解析（含追问与踩坑）→
2.一台 worker 挂掉了，这个信息如何发回数据平面？

worker 节点上的 kubelet 会周期性通过 Lease API 向 apiserver 上报心跳；Node Controller 监听这些 Lease，一旦超时未收到，就将节点状态置为 NotReady，并触发 Pod 驱逐、Endpoint 更新和重调度。整个过程不依赖数据平面主动上报，而是控制面主动探测。

回答要点
  1. 明确 kubelet 主动上报 Lease（非 NodeStatus 全量更新）
  2. 指出 Node Controller 是判断主体，且依赖超时阈值
  3. 说明后续动作：NotReady 状态、Pod 驱逐、EndpointSlice 摘除
完整解析（含追问与踩坑）→
3.K8s 中，你想把某一个 Pod 的东西复制到宿主机中，你应该怎么做？

用 kubectl cp 命令，格式是 kubectl cp /: ，多容器必须加 -c ；注意容器里得有 tar，因为底层靠 tar 打包传输。

回答要点
  1. 写出标准命令格式（含 namespace/pod/container-path/local-path）
  2. 强调多容器需指定 -c 参数
  3. 点出 tar 依赖和权限限制两个常见卡点
完整解析（含追问与踩坑）→
4.这个和 Docker 的 `cp` 命令有什么区别？

docker cp 是本地 daemon 到本地容器，走 Unix socket；kubectl cp 是客户端经 apiserver 转发到远端 kubelet，再进容器，路径要带 namespace/pod/container，底层依赖 tar 流和 API Server 中转。

回答要点
  1. 明确作用域差异：单机 vs 集群
  2. 指出通信路径差异：socket vs apiserver+kubelet
  3. 强调路径结构差异（namespace/pod/container）和底层依赖（tar）
完整解析（含追问与踩坑）→
5.进程和线程的区别是什么？

进程是资源分配单位，有独立地址空间、文件描述符表、信号处理等；线程是CPU调度单位，同一进程内线程共享地址空间、全局变量、打开的文件，但有独立栈、寄存器、线程ID；创建进程开销大，线程开销小；线程间通信快，进程间需IPC。

回答要点
  1. 明确资源分配 vs 调度单位的分工
  2. 指出共享项（地址空间、文件描述符）和独立项（栈、寄存器）
  3. 对比创建开销与通信成本
完整解析（含追问与踩坑）→
6.线程间通信有哪些？

主要有六种：共享内存配互斥锁、条件变量、信号量、管道、消息队列，还有 Go 里的 channel。关键是要匹配场景——比如需要解耦用消息队列，需要同步用条件变量，Go 开发优先 channel。

回答要点
  1. 至少列出四种标准 IPC 方式（锁/条件变量/信号量/管道/消息队列）
  2. 说明 channel 是语言特例而非通用机制
  3. 点出选择依据：同步需求 or 解耦需求
完整解析（含追问与踩坑）→
7.死锁的四个条件是什么？

死锁四必要条件：互斥（资源不能共享）、占有并等待（已占资源又申请新资源）、不可抢占（已占资源不能被强制释放）、循环等待（多个线程形成环形等待链）。缺一不可。

回答要点
  1. 完整准确复述四个条件名称
  2. 每个条件用一句话简释（如‘占有并等待’=持有A又申请B）
  3. 强调‘必要条件’而非充分条件
完整解析（含追问与踩坑）→
8.死锁避免？

我主要从破坏循环等待和占有并等待入手：一是固定加锁顺序，比如按资源 ID 升序获取；二是申请资源前先检查是否会导致死锁，像银行家算法；三是加锁超时自动释放，失败后退避重试。代码层面靠静态分析和 Code Review 卡住高风险模式。

回答要点
  1. 给出至少两种具体技术手段（如固定顺序/超时/银行家）
  2. 说明每种手段对应破坏哪个必要条件
  3. 补充工程实践（静态检查/Review）
完整解析（含追问与踩坑）→
9.TCP 为什么要四次挥手？如果省略第四次挥手，会有什么问题？

四次挥手因 TCP 全双工，双方需独立关闭发送方向。第一次 FIN 关 A→B 发送，第二次 ACK 确认，第三次 FIN 关 B→A 发送，第四次 ACK 确认。若省略第四次，B 不知 A 是否收到 FIN，可能重发 FIN，导致 A 无法进入 CLOSED，B 卡在 LAST_ACK，连接异常残留。

回答要点
  1. 说明全双工导致需双方独立关闭发送通道
  2. 准确描述四次交互中每次的发起方和含义
  3. 指出省略第四次会导致 B 卡在 LAST_ACK、A 无法释放资源
完整解析（含追问与踩坑）→
10.挥手中的 `TIME_WAIT` 是做什么用的？

TIME_WAIT 有两个硬作用：一是保证最后那个 ACK 丢了能重传，让被动关闭方可靠进入 CLOSED；二是等网络中所有属于旧连接的延迟报文自然消失，避免它们干扰新连接——特别是当新连接复用相同四元组时。

回答要点
  1. 明确写出两个作用：ACK 重传保障 + 旧报文清理
  2. 点出‘四元组复用’这个触发场景
  3. 强调这是主动关闭方必须承担的状态
完整解析（含追问与踩坑）→
11.解释一下 `O(1)`、`O(n)`、`O(log n)`、`O(n^2)`，并举例场景。

O(1) 是常数时间，比如数组按索引取值；O(n) 是线性，比如遍历找最大值；O(log n) 是对数，比如二分查找；O(n²) 是平方，比如冒泡排序或矩阵乘法。重点看操作次数是否随输入规模增长而倍增。

回答要点
  1. 每个复杂度配一个无争议经典例子
  2. 例子必须体现‘操作次数与 n 的关系’
  3. O(1) 必须是非迭代/非递归的确定性操作
完整解析（含追问与踩坑）→
12.数组和链表的区别是什么？优缺点是什么？有什么使用场景？

数组内存连续，随机访问 O(1)，但插入删除 O(n)；链表节点分散，插入删除 O(1)（已知位置），但访问 O(n)。数组缓存友好适合批量读写；链表适合频繁中间增删，比如 LRU 缓存。实际选型看访问模式和修改频率。

回答要点
  1. 对比内存布局、访问/增删时间复杂度
  2. 点出缓存局部性对数组性能的影响
  3. 给出各一个典型场景（如数组→批量统计，链表→LRU）
完整解析（含追问与踩坑）→
13.服务器负载较高你会怎么排查？

我按五层定位：先 uptime/top 看 load 和 CPU；再 pidstat/top -H 定位高耗进程线程；然后 free/vmstat 查内存和 swap；接着 iostat/iotop 看磁盘 IO；最后 ss/sar -n 看网络连接和重传。同时查应用日志、错误率、GC 和依赖服务延迟。

回答要点
  1. 覆盖 CPU/内存/磁盘/网络/应用五层
  2. 每层给出 1–2 个必用命令（如 iostat、ss）
  3. 强调结合日志和监控曲线交叉验证
完整解析（含追问与踩坑）→

15.算法：求一个字符串的最长回文子串。

我用中心扩展法：遍历每个字符，以它为中心向两边扩展，同时处理奇偶长度（i,i）和（i,i+1）；维护 start/end 记录最长位置，最后返回子串。时间 O(n²)，空间 O(1)，代码简洁易讲。

回答要点
  1. 明确选择中心扩展法（非 DP）
  2. 写出核心逻辑：双指针扩展 + 奇偶双起点
  3. 说明复杂度并指出优势（代码短、易调试）
完整解析（含追问与踩坑）→
