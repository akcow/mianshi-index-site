这一场问了什么

1.描述一个线程从创建开始的完整生命周期。

线程生命周期包括新建、就绪、运行、阻塞和终止五个状态：new后调start进入就绪；被调度器选中进入运行；遇到I/O或wait进入阻塞；阻塞结束回到就绪；run方法执行完或调stop进入终止。注意Java中已废弃stop，实际以自然退出或interrupt为终态。

回答要点
  1. 明确列出5个标准状态名称
  2. 说明各状态间转换触发条件（如start→就绪、wait→阻塞）
  3. 指出Java中终止状态的实际达成方式（非stop）
完整解析（含追问与踩坑）→
2.从JVM角度讲一下Java创建线程的生命周期。

JVM线程是OS线程的轻量级封装，new Thread()只创建Java对象；调start()才真正向OS申请内核线程，并为该线程分配独立的Java虚拟机栈和PC寄存器，堆内存仍共享。线程死亡后，JVM栈被回收，但OS线程资源需由系统调度器释放。

回答要点
  1. 区分Java Thread对象创建与OS线程创建时机
  2. 说明JVM栈、PC寄存器为线程私有，堆为共享
  3. 指出线程终止后JVM栈立即回收，OS线程资源异步释放
完整解析（含追问与踩坑）→
3.count计数（add和get），用你知道的方式改成线程安全的，可以写多种，不要求能运行。

三种方式：一是用synchronized关键字修饰add和get方法，保证同一时刻只有一个线程执行；二是用AtomicInteger，靠CAS实现无锁原子更新；三是用ReentrantLock显式加锁，在add和get里lock/unlock。注意synchronized和ReentrantLock都需保证读写都加锁才一致，而AtomicInteger天然支持原子读写。

回答要点
  1. 写出synchronized方法实现
  2. 写出AtomicInteger.getAndIncrement()调用
  3. 写出ReentrantLock.lock()/unlock()包裹逻辑
完整解析（含追问与踩坑）→
4.volatile了解吗？解决了什么问题？

volatile主要解决两个问题：一是保证变量修改对其他线程立即可见，避免线程缓存旧值；二是禁止JVM和CPU对该变量的读写指令重排序。但它不保证原子性，比如i++这种复合操作依然线程不安全，也不能替代锁来保护临界区。

回答要点
  1. 准确说出‘可见性’和‘禁止重排序’两大作用
  2. 明确指出不保证原子性
  3. 举例说明i++为何仍不安全
完整解析（含追问与踩坑）→
5.MySQL 索引的底层原理是什么，它解决了什么问题？

先开slow_query_log，设long_query_time阈值；用mysqldumpslow或pt-query-digest分析日志找TOP SQL；再explain看执行计划，重点看type、rows、key、Extra；最后结合索引、SQL写法、数据量做针对性优化，比如加索引、改JOIN顺序、拆分大事务。

回答要点
  1. InnoDB 用 B+ 树：非叶子节点只存键，叶子节点存数据且用链表相连
  2. B+ 树矮胖，三层能存千万级数据，把随机 IO 压到 2-3 次
  3. 相比全表扫描 O(n)，索引把查找降到 O(log n)
  4. 叶子链表支持范围查询和排序，这是 B+ 树相对 B 树的关键优势
完整解析（含追问与踩坑）→
6.update这个语句会加什么锁？

在RC和RR隔离级别下，update会先对id=10这行加X（排他）记录锁；如果id是二级索引且不是唯一索引，还会加gap锁防止幻读；如果是唯一索引等值查询，则只加记录锁。注意：即使where条件没走索引，也会对所有扫描行加锁，可能升级为表锁。

回答要点
  1. 明确X记录锁是基础
  2. 说明gap锁在非唯一二级索引下的存在
  3. 指出唯一索引等值查询不加gap锁
完整解析（含追问与踩坑）→
7.请讲讲 redo log 和 undo log。

redo log是重做日志，保障持久性：事务提交时先写redo log，再异步刷数据页，宕机后靠它恢复已提交修改；undo log是回滚日志，保障原子性：记录修改前旧值，回滚时用它复原，还支撑MVCC快照读。两者配合，才让ACID落地。

回答要点
  1. redo log→持久性→WAL→崩溃恢复
  2. undo log→原子性→回滚→MVCC
  3. 点明二者协同实现ACID
完整解析（含追问与踩坑）→
8.讲一下Function call、MCP、skill、rules、vibe coding、spec coding、harness engineering的概念以及解决了什么问题。

Function call是模型调用预定义工具API，解决确定性任务；MCP（Model Context Protocol）是标准化工具注册与调用协议，让不同模型能复用同一套工具；Skill是可组合的原子能力单元；Rules是硬性约束；Vibe coding靠提示词引导风格；Spec coding用结构化schema定义输入输出；Harness engineering指构建测试沙箱验证Agent行为。它们共同解决LLM不可控、难调试、难集成的问题。

回答要点
  1. Function call=调用API，MCP=工具通信协议
  2. Skill=可复用原子能力，Rules=不可违反约束
  3. Spec coding=Schema驱动，Harness=沙箱验证
完整解析（含追问与踩坑）→
9.ReAct 模式和 Plan 模式有什么区别，各自适用于什么场景？
回答要点
  1. ReAct：思考-行动-观察循环，每步依赖上一步结果，适合探索型、信息不完备的任务
  2. Plan：先产出完整计划再执行，适合步骤可预先枚举、需要全局最优的任务
  3. ReAct 灵活但容易绕路、成本不可控；Plan 可控但对环境变化适应性差
  4. 实践中常见混合：先 Plan 出骨架，执行中在子任务内用 ReAct
